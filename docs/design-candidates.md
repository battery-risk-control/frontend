# 화면 설계 후보 (보류, 폐기 아님)

## 원자재 가격 추이 — 화면 구성 후보 (2026-07-22 결정 보류)

결정: 2026-07-22, "전체보기" 탭 제거, "상세보기"(필터+요약카드+멀티라인) 단독 유지. 사유: (1) 원자재 드롭다운을 "전체"로 두면 전체보기와 내용이 중복됨, (2) surin 스타일 후보들보다 현재 상세보기가 더 낫다고 판단.

전제: 아래 두 후보는 모두 "컴팩트 뷰(전체보기에 해당) + 상세 뷰"라는 2단계 구조를 전제로 설계되었다. 지금 컴팩트 뷰(전체보기)가 삭제된 상태이므로, 이 후보를 재검토하려면 컴팩트 뷰에 해당하는 진입점을 다시 만들어야 한다.

### 후보 A — surin Dashboard.tsx 위젯형
(자재 탭 전환으로 하나씩 선택 + 큰 현재가 숫자 + 단일 계열 차트 + 기간 버튼 3M/6M/1Y/2Y + "상세 분석" 버튼으로 상세 뷰 진입)

### 후보 B — 버튼 클릭 확장형 인터랙션
(평소엔 컴팩트 뷰만 노출, 그 안의 "상세 분석" 버튼을 눌러야 상세 뷰가 나타나는 구조 — 후보 A와 조합 가능)

## 공개 대시보드 좁은 화면 콘텐츠 신호 — 후보 (2026-07-23)

배경: 좁은 화면(760px 미만)에서 그리드가 2x2에서 1열 4행으로 전환되며 하단 콘텐츠 신호(ScrollHint, A안 — 하단 그라데이션+화살표)를 실험적으로 도입. 아래 두 대안은 검토했으나 이번 범위에서는 채택하지 않음.

- 도트 인디케이터 — 카드가 실제로 이름 붙은 독립 섹션으로 재구성될 때(점프 이동 가능할 때) 재검토. 지금처럼 단순 스크롤 구조에는 부적합하다고 판단(2026-07-23).
- 컷오프 기법 — 그리드를 뷰포트의 ~90% 높이로 배치해 다음 카드가 살짝 잘려 보이게 하는 방식. 화살표 없이도 스크롤 가능함을 암시할 수 있으나, 현재 grid-template-rows 구조 전체 재설계가 필요해 이번 실험 범위를 벗어난다. 전체 반응형 Phase에서 재검토.

## 구매팀 대시보드 UX-01-DB 반영 시 검토했으나 보류한 대안 (Phase 9.4, 2026-07-24)

- **① `MaterialRiskStatusPanel` 내부 자재별 집계 표시안** — 데모의 5칸 게이지 그리드를 별도
  섹션으로 신설하지 않고, 기존 `MaterialRiskStatusPanel`(원자재 공급사 리스크 현황) 리스트
  상단에 자재별(리튬/니켈/코발트) 집계 게이지를 추가하는 방식도 검토했다. 채택하지 않은 이유:
  데모/surin 원본에서 이 요약 영역은 개별 리스크 이벤트 리스트와 별개의 독립 섹션이고, 자재
  구성(surin 3종: 리튬/니켈/흑연)이 `risk_event` mock 자재 구성(니켈/리튬/코발트)과 달라 한
  리스트 안에 섞으면 두 자재 집합의 불일치가 더 눈에 띄게 충돌한다. 별도 `MaterialRiskOverviewRow`
  신설로 대체.
- **③ `ErpImpactPanel` 서브섹션 분리안** — ERP 영향 자재 재고 계약 분석 패널을 "재고 현황"/
  "품질 검증" 두 서브섹션으로 쪼개는 방식도 검토했다. 채택하지 않은 이유: 이번 작업 범위(데모
  요약 영역 신설 + ScrollCard 통일 + SideNav 접기)와 무관한 별도 리팩터이고, 현재 리스트 구조로도
  카드 레이아웃·스크롤 규칙(design-tokens.md)을 이미 만족해 굳이 구조를 바꿀 필요가 없었다.
  현재 리스트 구조를 그대로 유지하기로 결정.

## C1 — 리스크 유형별 분포 차트 (별도 Phase, 착수 전, 2026-07-24)

product-overview.md "MVP 범위"에 "유형별 분포 차트"가 필수 항목으로 명시돼 있으나(Seq
번호 없음 — `요구사항_정의서.xlsx`/`docs/requirements-frontend.md` 쪽에는 이 항목 자체가
없음, 별도 출처인 "프로젝트_기획_정의서 v2"에만 등장), 착수 전 확인이 필요한 미결 사항을
기록해 둔다. 아직 구현 착수하지 않았다.

- **스키마 공백**: `risk_event`(CLAUDE.md 원본 스키마) 최상위 8개 필드 및 `market_context`
  하위 필드를 전수 확인한 결과 "유형"/"category"/"event_type"/"issue" 계열 필드가 전혀 없다
  (`src/api/types.ts`의 `RiskEvent`도 CLAUDE.md 스키마와 정확히 일치, 동일하게 없음). "리스크
  유형" 개념 자체가 mock 데이터에 아직 존재하지 않으므로, 착수 시 신규 필드 설계가 선행돼야
  한다.
- **카테고리 출처 후보 2가지(확정 아님)**:
  - (a) GDELT 이벤트유형 기반 — 기획정의서에 "예: 수출제한/광산사고/관세/재고소진"이 언급되나
    이는 예시일 뿐 확정된 값 목록이 아니다.
  - (b) 데모 이미지의 "주요 리스크 드라이버" 고정 4종(수출규제/광산차질/정책변화/물류지연) —
    단, 이 요소는 데모상 대시보드(1, `UX-01-DB`) 화면이 아니라 **"외부 리스크 모니터링"
    (2, `UX-02-RM`) 화면 소속**이다. 우리 레포의 `PurchasingDashboardPage`(1계층 구매팀
    대시보드)와 화면 성격이 다를 수 있음에 유의.
- **배치 화면 미결**: 현재 작업 중인 `PurchasingDashboardPage`에 넣을지, 아니면 데모처럼
  별도 화면(외부 리스크 모니터링에 해당하는 신규 페이지/라우트, 현재 레포엔 존재하지 않음)을
  신설해야 할지 확인이 필요하다.

## C2 — "ERP 영향 분석" 화면 부재 (별도 Phase, 착수 전, 2026-07-24)

surin에는 `pages/ErpImpact.tsx`(`/erp-impact` 라우트, 네비 라벨 "ERP 영향 분석")로 존재하고
데모 이미지(`ChatGPT Image 2026년 7월 9일 오전 10_50_58 (3).png`)에도 등장하는 화면이지만,
`docs/requirements-frontend.md`(Seq 1~36 체계)에는 이 화면에 대응하는 Seq 항목이 없고
우리 레포에도 구현이 없다. 착수 전 확인이 필요한 갭만 기록해 둔다. 아직 구현 착수하지 않았다.

- 이 화면의 "자재 영향도 분포" 도넛(영향도 점수 구간 높음 80~100=14건/주의 50~79=20건/
  보통 20~49=10건/낮음 0~19=4건)은 **C1(리스크 유형별 분포 차트)과는 다른 축**이다 — C1은
  "리스크 유형"(아직 스키마에 없는 개념) 기준 분포, 이건 "ERP 영향도 점수 구간" 기준 분포다.
  따라서 C1 해결책(리스크 유형별 분포 차트 구현)으로 이 화면의 부재를 대신 해소할 수 없다.
- 착수 여부·우선순위는 미결정 상태로 남긴다.
