## 원자재 가격 추이 — 화면 구성 후보 (2026-07-22 결정 보류)

결정: 2026-07-22, "전체보기" 탭 제거, "상세보기"(필터+요약카드+멀티라인) 단독 유지. 사유: (1) 원자재 드롭다운을 "전체"로 두면 전체보기와 내용이 중복됨, (2) surin 스타일 후보들보다 현재 상세보기가 더 낫다고 판단.

전제: 아래 두 후보는 모두 "컴팩트 뷰(전체보기에 해당) + 상세 뷰"라는 2단계 구조를 전제로 설계되었다. 지금 컴팩트 뷰(전체보기)가 삭제된 상태이므로, 이 후보를 재검토하려면 컴팩트 뷰에 해당하는 진입점을 다시 만들어야 한다.

### 후보 A — surin Dashboard.tsx 위젯형
(자재 탭 전환으로 하나씩 선택 + 큰 현재가 숫자 + 단일 계열 차트 + 기간 버튼 3M/6M/1Y/2Y + "상세 분석" 버튼으로 상세 뷰 진입)

### 후보 B — 버튼 클릭 확장형 인터랙션
(평소엔 컴팩트 뷰만 노출, 그 안의 "상세 분석" 버튼을 눌러야 상세 뷰가 나타나는 구조 — 후보 A와 조합 가능)

## 공개 대시보드 좁은 화면 콘텐츠 신호 — 후보 (2026-07-23, 2026-07-26 결정 번복)

배경: 좁은 화면(760px 미만)에서 그리드가 2x2에서 1열 4행으로 전환되며 하단 콘텐츠 신호(ScrollHint, A안 — 하단 그라데이션+화살표)를 실험적으로 도입. 아래 두 대안은 2026-07-23 시점엔 검토 후 채택하지 않았으나(이유는 아래 각 항목에 원문 그대로 남김), **2026-07-26 구매팀 대시보드(도트 인디케이터)/공개 대시보드(컷오프 기법) 작업에서 실제로 채택**했다 — 아래는 그 경위.

- **도트 인디케이터** — 2026-07-23 당시 사유: "카드가 실제로 이름 붙은 독립 섹션으로 재구성될 때(점프 이동 가능할 때) 재검토. 지금처럼 단순 스크롤 구조에는 부적합하다고 판단." → 2026-07-26: 구매팀 대시보드에 데모(UX-01-DB) 구조 반영(Phase 9.4) 이후 8개의 이름 붙은 독립 섹션(상단 KPI 요약~구매 대응 우선순위)이 이미 존재해 위 보류 조건이 해소됐다고 판단, `components/ui/PageSectionDots/` 신규 컴포넌트로 구매팀 대시보드에 채택(공개 대시보드에는 미적용 — 공개 대시보드는 여전히 4개 카드뿐인 단순 스크롤 구조라 이 컴포넌트의 `variant='standalone'`은 아직 실제 소비처 없음).
- **컷오프 기법** — 2026-07-23 당시 사유: "그리드를 뷰포트의 ~90% 높이로 배치해 다음 카드가 살짝 잘려 보이게 하는 방식... 현재 grid-template-rows 구조 전체 재설계가 필요해 이번 실험 범위를 벗어난다." → 2026-07-26: 실제로 시도해보니 전체 재설계는 불필요했다 — `.page`를 `min-height:100vh`(페이지 자체가 자라며 document가 스크롤)에서 `height:100vh; overflow-y:auto`(`.page` 자신이 스크롤 컨테이너)로 바꾸고, `.grid`의 행 크기를 `minmax(320px, 1fr)`→`minmax(320px, auto)`로 한 줄만 바꾸는 것으로 충분했다(1fr을 쓰면 `.grid`가 `.page`보다 커지는 오버플로 상태에서 남는 공간을 카드 내부 빈 여백으로 억지로 채우는 부작용이 실측으로 확인돼 auto로 교체). 데스크톱(1280x800)/모바일(375x812) 모두 Playwright 스크린샷으로 다음 행/카드가 자연스럽게 일부만 보이는 효과를 확인, 기존 `ScrollHint`(IntersectionObserver 기반 안내) 사용을 제거하고 이 레이아웃 기법으로 대체했다. `ScrollHint` 컴포넌트 자체(`components/ui/ScrollHint/`)는 소비처 소멸 확인 후 2026-07-26 별도 커밋으로 완전히 삭제했다(`docs/design-tokens.md` "카드 레이아웃·스크롤 규칙" a 참고).

## 구매팀 대시보드 UX-01-DB 반영 시 검토했으나 보류한 대안 (Phase 9.4, 2026-07-24)

- **① `MaterialRiskStatusPanel` 내부 자재별 집계 표시안** — 데모의 5칸 게이지 그리드를 별도
  섹션으로 신설하지 않고, 기존 `MaterialRiskStatusPanel`(원자재 공급사 리스크 현황) 리스트
  상단에 자재별(리튬/니켈/코발트) 집계 게이지를 추가하는 방식도 검토했다. 채택하지 않은 이유:
  데모/surin 원본에서 이 요약 영역은 개별 리스크 이벤트 리스트와 별개의 독립 섹션이고, 자재
  구성(surin 3종: 리튬/니켈/흑연)이 `risk_event` mock 자재 구성(니켈/리튬/코발트)과 달라 한
  리스트 안에 섞으면 두 자재 집합의 불일치가 더 눈에 띄게 충돌한다. 별도 `MaterialRiskOverviewRow`
  신설로 대체.
- **③ `ErpImpactPanel` 서브섹션 분리안** — ERP 영향 자재 재고 계약 분석 패널을 "재고 현황"/
  "품질 검증" 두 서브섹션으로 쪼개는 방식도 검토했다. 채택하지 않은 이유: 이번 작업 범위(데모
  요약 영역 신설 + ScrollCard 통일 + SideNav 접기)와 무관한 별도 리팩터이고, 현재 리스트 구조로도
  카드 레이아웃·스크롤 규칙(design-tokens.md)을 이미 만족해 굳이 구조를 바꿀 필요가 없었다.
  현재 리스트 구조를 그대로 유지하기로 결정.
