# QA 체크리스트 — 화면 간 일관성 점검

> 이번에 발견된 문제(공개 대시보드가 Header 갱신에서 누락됨)처럼, 공용 요소를
> 바꿀 때 일부 화면만 갱신되고 나머지가 방치되는 패턴이 반복되지 않도록 만든
> 체크리스트다. **새 Phase 시작 전, 그리고 merge/이식 작업 직후 반드시 재실행한다.**

## A. 인증 상태 표시 일관성
- [ ] 로그인 상태에 따른 UI(계정 정보/로그아웃 vs 로그인/회원가입 버튼)가 **모든 화면**(공개 대시보드 포함)에서 동일한 소스(`Header` 등 공용 컴포넌트)를 통해 표시되는가?
- [ ] 새로 추가된 화면이 있다면, 그 화면도 이 목록에 포함해 검토했는가?

## B. 공용 컴포넌트 변경 시 파급 범위
- [ ] `components/layout` 또는 `components/ui`의 컴포넌트를 바꿀 때, 그걸 사용하는 **모든** 화면을 grep으로 확인했는가?
- [ ] 반대로, 공용 컴포넌트를 써야 하는데 화면이 자체 UI를 별도로 구현하고 있지 않은가? (이번 문제의 원인)

## C. 접근 제어·리다이렉트의 사용자 피드백
- [ ] 접근이 막히거나 리다이렉트될 때, 사용자가 "왜" 이동됐는지 알 수 있는가? (무음 리다이렉트는 혼란을 유발)
- [ ] 확인/취소류 대화상자가 있다면, 기본 선택지(포커스)가 안전한 쪽(대개 취소/현재 유지)인가?

## D. 클릭 가능 요소의 시각적 신호
- [ ] 텍스트나 로고가 링크 역할을 겸할 때, 아이콘·hover·커서 변화 등으로 클릭 가능함이 드러나는가?

## E. 요구사항 대비 커버리지
- [ ] 새 화면/기능이 `docs/requirements-frontend.md`의 해당 Seq 항목을 빠짐없이 반영했는가?
- [ ] `docs/mock-schemas.md`가 실제 코드와 어긋난 부분은 없는가?

## F. 공용 레이아웃 컴포넌트 사용 일관성
- [ ] 카드형 UI가 지정된 공용 컴포넌트(ScrollCard 등)를 쓰는가, 자체 `.panel` 스타일을 새로 만들지 않았는가?
- [ ] 콘텐츠 유형(리스트/차트/폼)에 맞게 스크롤 옵션(`scrollable` 등)이 설정됐는가? 그래프 콘텐츠는 스크롤 대상에서 제외됐는가?

## G. 트러블슈팅/실험 잔존물 정리
- [ ] 이번 Phase 중 생성된 임시 검증 스크립트, 되돌린 실험 코드, 미사용 import/상태가 최종 커밋에 안 남아있는가?
- [ ] `git status`가 의도한 파일만 표시하는가?

## H. 보고/회귀 점검
- [ ] 지시문에 번호/항목이 있으면, 보고도 같은 번호/항목별로 ✅/❌ 명시했는가? 서술형 요약만으로 대체하지 않았는가?
- [ ] 레이아웃 값(위치/간격/크기)을 바꾸는 커밋에서, 바꾸려던 값과 인접해서 파생되는 값(간격, 부모 폭, 형제 요소 크기 등)을 모두 실측해 커밋 메시지에 함께 남겼는가?

## 실행 시점
Phase 종결 시점마다 A~H를 실제로 순회하고, 그 결과를 커밋 메시지 본문에 명시한다(강제). CLAUDE.md import만으로 참조해두는 것으로 충분하지 않으며, 매 Phase 종결 보고에 이 점검이 빠지면 안 된다.
